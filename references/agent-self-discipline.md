# 主代理自约束面（派发前的等价面）

> 出处：`LRN-20261018-011`。定位 = **`LRN-20261015-001` 对主代理自身的执行面**——
> 那条规则要求「给子代理的规则要写在它有工具能读到的地方」，
> 本文件是同一要求施加于主代理自己的产物。
> 规程型条目（`guard_ref: null` + `skill_ref` 指向本节），按 schema §1.4 不计入六拍达成率。

## §0 为什么要有这一节

全局规则《子代理编排》要求**每次派发子代理都在任务说明开头附强制约束块**。
**主代理派发自己时不附**——于是子代理每轮都拿到结构化边界、不试探；
主代理每轮空手入场、重新试探。这是同一个洞的两面。

2026-10-18 实测：本会话第 1 条消息即授权修改 skills，到第 12 条为止重复确认至少 4 次，
用户第 12 条原话「这个话题一开头我就已经授权你去修改skills，你还在这那这个借口??？」。

## §1 三条纪律

### §1.1 授权是状态，存在对话散文里必然衰减

一轮对话内用户给出的授权 = **本话题全部后续动作的持续授权**。
它不是一次性通行证，也不是每轮都要重新举证的申请。

**判据：授权必须存在「决策时刻会重读的地方」。对话散文不算位置。**
散文只在生成时有效；第 N 轮决定要不要做 X 时我读的是当前上下文，
而那句授权是 12 轮前的一句自然语言，没有绑定到「现在这个决策」上。
于是每轮退化成从零重建全部已决事实 → 重建带噪声 → 噪声触发提问 → 用户重复输入。

**动作**：话题开始即建 `.learnings-work/session-facts.md`（本仓 gitignored 工作态，
正确的家），每轮开头读一次、轮内改一次。字段见 §2。

### §1.2 可逆本地动作默认不问

| 类别 | 判据 | 动作 |
|---|---|---|
| 可逆 · 本地 · 不出站 | 改文件、`git add`/`commit`/`mv` 到本地分支、跑只读门禁、重跑测试、`git stash` | **不问，直接做** |
| 不可逆 | `reset --hard` / `clean` / `branch -D` / `stash drop·clear` / `push --force` | 先问 |
| 出站 | `push` / deploy / 任何镜像与远端环境动作 | 先问 |
| 他人数据 | 删别人的工作树 / 分支 / 暂存 | 先问 |
| 基础配置 | `AgentRuntimeConfig` 表、`config/agent-runtimes.yaml`、`.env` 运行时键 | 先问且逐字核对原值 |

「能不能撤销」不是分界线，「撤销会不会丢别人已投入的东西 / 会不会离开本地」才是。
把可逆当不可逆 = 把九成日常动作升级成请示，这是拖沓的第二个来源。

### §1.3 收尾不得以问句交付本该我做的动作

「要我出 X 的 diff 吗」「这两个要一起落吗」都是**决策外流**：
本该我承担的一次判断，被换成用户的又一次点击，而用户还得重新解释已给过的授权。

用户感知到的拖沓不是执行慢，是**决策权反复外流**——每次外流都要他重新进入上下文。

**要么做了并报告，要么说明为何做不了。不给只值一次点击的假选项。**

### §1.4 附带：没验证过的不写「已`

本会话把写在 `.gitignore` 目录（`docs/*`）里的交接文档汇报成「已提交」，
实际从未进版本控制（根因见 `ERR-20261018-021`）。
假完成信号会让自己跳过验证，下一轮才发现，返工成本比当场验证高一个数量级。

**每条「已完成」标注验证方式**（命令 / `git cat-file -e` / 门禁退出码），
没验证的写「已写入未验证」。

## §2 `.learnings-work/session-facts.md` 台账字段

```markdown
# 本话题已决事实
授权范围: <一句话，含原句引用>   # 一次性授权在此转为可重读状态
不可逆清单: <本话题内需问的操作>   # 空则写「无」
已完成: <条目 + 验证方式>
剩余: <未做项>
决策外流禁令: 收尾不以问句交付本该我做的动作
```

放 gitignored 工作态而非入库：它是**当前会话**的状态，不是项目知识。
跨会话需要留存的结论走 `.learnings/` 条目（本文件 §1 各条即该沉淀的形态）。

## §3 注入点（2026-10-18 已闭合 · 落点选错过一次）

本文件原先自陈的天花板：**不被宿主每轮注入的文件指向 = 规程等于不存在**。

**第一次落点选错**：先按 `LRN-20261018-015-001` 说的「SKELETON §2 触发矩阵」加了指针行，
随后 `git add` 静默跳过暴露真相 —— **`.agents/rules/SKELETON.md` 与 `loc-dev.md`
都被本机 gitignore/exclude 类机制排除、根本不入库**（`LRN-20261018-004` 已记同一事实）。
往那里写 = 只在本机有效，跨会话跨机器零传播，**比不写更坏**：它制造「我以为修好了」的假象。

**正确落点 = 根 `AGENTS.md` §「域 skill 强约束索引」表加一行**：
该文件既被宿主每轮注入、又入库，是本仓唯一同时满足两个条件的规则文件。

| 层级 | 形态 | 强制力 |
|---|---|---|
| 跨会话 | 根 `AGENTS.md` 指针行（每轮注入 + 入库） | 加载触发 |
| 话题内 | `.learnings-work/session-facts.md` 台账（每轮开头读） | 自愈台账 |

**判据（下次选落点先跑这条）**：`git ls-files --error-unmatch <候选文件>` ——
不返回路径就是不入库，**不入库的文件不能当跨会话强制点**，无论它是否被宿主注入。

未做的部分（诚实声明）：本节仍是**规程**不是**门禁**——
`AGENTS.md` 的加载靠我自觉，没有钩子能检查「本轮是否问了不该问的」。
真要门禁化需要一个可机检的代理（如对 turn 文本做「授权已给 + 又提问」的模式匹配），
当前成本高于收益，未做。
