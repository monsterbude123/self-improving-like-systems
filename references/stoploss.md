# 止损程序 —— 冻结 / 恢复（票 13）

> **一句话**：经验系统是「让机器替人记住教训」的机制，它一旦开始**往人的上下文里注入东西**，
> 出错的方向就变成了「把错的教训注入进去」而不是「没学到教训」—— 后者只是浪费，前者污染工作。
> 所以止损线卡在**注入**而不是捕获：**只保留事件捕获（它是纯事实、只增不改、零注入），
> 停掉一切会主动改变人的行为的部分。**

## 0. 三开关的极性（**先读这一节，写反就是事故**）

判据是**源码唯一**的：三开关一律 **`true` = 该路径开**（产生副作用）**、**`false` = 该路径停****`false` = 该路径停**（零副作用）。
`inject.mjs` / `hook-session-start.mjs` / `capture.mjs` / `distill.mjs` 的守卫写法都是
`if (config.kill_switch.X !== true) → 跳过`，即**不是 true 就不做**。

| 开关 | 判据出处 | `true` = | `false` = |
|---|---|---|---|
| `kill_switch.injection: <bool>` | `../scripts/inject.mjs`、`../scripts/hook-session-start.mjs` | 注入开 | **注入停** |
| `kill_switch.distill: <bool>` | `../scripts/distill.mjs` | 蒸馏开 | **蒸馏停** |
| `kill_switch.capture: <bool>` | `../scripts/capture.mjs` | 捕获开 | **捕获停** |

⚠️ 反例（本文件 2026-10-16 前踩过）：把「停注入」写成**打开**注入开关（值写开启侧）——
那不是止损，是**打开注入**并留下捕获，恰好把「纯事实」变成「持续污染」，与本程序的目的正好相反。
`tests/stoploss.test.mjs` 会把本文件里每一个 `kill_switch.X: <bool>` 表述与上面这张表（由脚本源码反推）逐条对拍，
写反即测试变红。

## 1. 触发条件（谁来说）

`scripts/trace.mjs` 的判定退出码 **1 = 触发冻结**。判据是二值的、可复跑的：

| 判定 | 含义 | 退出码 |
|---|---|---|
| 通过 | ≥1 条**真实**条目自然走完六拍（事件 → 条目 → 守卫登记 → 守卫运行 → 拦截 → 回写），全链有行级引用 | `0` |
| 触发冻结 | 无任何条目走完六拍 —— 系统要么没真跑起来，要么跑起来的证据链断在某一拍 | `1` |
| 无法判定 | 用法错误 / 数据源非法（registry 或守卫状态**损坏**；配置的数据源指向夹具目录） | `2` |

**exit 2 ≠ exit 1**：exit 2 是「读不到事实」（去修数据），exit 1 是「事实就是没走完」（去止损）。
把两者混同会让「登记表写坏了」被当成「系统坏了」，从而停掉一个其实健康的东西。

**新项目刚接入、还没有真实条目时，判定必然是 1** —— 这是如实，不是故障：
冻结是「还没证明自己之前不许注入」的默认值，不是失败判刑。

## 2. 冻结 = 做什么 / 不做什么

**做（保持运行）**

- 事件捕获（`capture.mjs`）：继续写事件库。事件是**纯事实**：只增不改、天然 append，
  不影响任何人的上下文，冻结期它是唯一的合法活动。
- 对账（`trace.mjs --dry-run` 等只读视图）：继续可跑，用于观察是否恢复到可解冻。

**不做（立即停）**

1. **停注入**：`kill_switch.injection: false`（注入引擎与 SessionStart 接线都读它；
   置 `false` 即「不是 true 就不注入」）。这是**唯一一条会主动改变人的行为**的路径，故止损线首先切它。
2. **停蒸馏**：`kill_switch.distill: false` —— 不再自动聚簇出草案。
   草案本身无害，但「持续产出待审草案」会让噪声压过信号。
3. **保留捕获**：`kill_switch.capture: true` —— 冻结期**要开着**（事件是纯事实、零注入）。
   只有决定「停捕获」时（那是另一个决定，须单独授权）才把它置 `kill_switch.capture: false`。
4. **停一切新功能**：本技能后续新增的能力（以及任何接线改动）在冻结期内一律不启用。
5. **停接线变更**：`references/hook-wiring*.json` 三片段**继续只出片段不接线**
   （片段仓库规则与冻结无关，见 `hook-wiring.md`；接线是行为变更，须解冻后单独决策）。

**明确不在冻结范围内**：条目、事件、守卫注册表**一律不删不改**。冻结是「不再产生新动作」，
不是「回滚已发生的事实」—— 已有语料是资产，也是将来解冻后复盘的依据。

## 3. 执行清单（可直接照做）

1. 跑一次对账把现状存证：`node scripts/trace.mjs --json > <某处>.json`（证据先落地，再动手）。
2. 改实例配置（**仓根 `.self-improving.yaml`，属产品配置非规则层**）把两个行为开关**停**：
   `kill_switch.injection: false` / `kill_switch.distill: false`；
   `kill_switch.capture: true` **保留开着**（冻结期继续捕获纯事实）。
   ⚠️ 改 `kill_switch` 是行为开关，按本仓纪律须**用户当窗显式授权**后才可落盘。
3. 重跑 `node scripts/trace.mjs --config <仓根>/.self-improving.yaml` 确认注入确已归零
   （审计日志里不再出现 `injected` 记录）。
4. 在条目区留一条说明为什么冻结（人读，不是机器读）—— 建议用 `status: investigating` 的新条目，
   或在本文件旁的项目侧记录里写一行，避免「冻结了但没人知道为什么」。

## 4. 恢复（解冻）

**恢复必须由用户显式发起**，不接受「trace 变绿了就自动恢复」—— 自动化掉的是人的判断，
而这正是止损线要保的东西。恢复步骤：

1. 用户显式要求解冻（当窗发言，含 `解冻` / `恢复注入` / `unfreeze` 之类明确动词）。
2. **先跑破坏测试，把「拦截命中」这一拍做实**（2026-10-17 修正 · 顺序反了会死锁）：
   对已登记的守卫喂一条**确实违规**的输入，走真实派发路径，让账上出现一次拦截。
   **这一步必须带 `--probe`**（破坏测试 = probe，其命中**不构成退役证据**、不回写条目正文；
   见下方「为什么必须带 `--probe`」）：
   ```bash
   node scripts/run-guard.mjs --probe --key <守卫key> --text '<确实违规的判据输入>'
   node scripts/verify.mjs --sweep          # 结清 probe 账（不改条目正文）；只有 wild 命中才回写 recurrence / 对质段
   ```
   拦不住就不是「解冻」，是「事故复现」。
   **为什么必须排在 trace 之前**：拍5 的判据是「这条链上确实有拦截证据」，
   而在没有真实违规可捕获时，唯一诚实的证据来源就是这次破坏测试（probe 路径，判据见
   schema.md §3.1.1 与本节末尾的拍5/拍6 两型表）。旧顺序要求先 trace 变 0 再做破坏测试，
   等于要求「证明已经证明过之后再去证明」——拍5 永远红，trace 永远 1，恢复永远被拒。

   **为什么必须带 `--probe`（不写进代码就必然记错账的那条纪律）**：
   破坏测试与真实路由走**同一个 CLI 入口**。不标来源时，「我们自己造出来验证守卫能用的违规」
   与「野外真发生的违规」在账上完全不可分，而两者证据强度差一个数量级：

   | | 不带 `--probe`（wild） | 带 `--probe`（probe） |
   |---|---|---|
   | 守卫级 `ever_hit` | 置位（**退役证据的门槛**） | **永不置位** |
   | 条目 `recurrence` / 正文对质段 | sweep 回写 | **一个字都不写** |
   | 拍5 判绿 | ✅（`wild_hits ≥ 1` + `first_wild_hit`） | ✅ 替代路径：`probe_hits ≥ 1` 且末次 `probe_last_outcome == proven` 且证据龄 ≤ `cycle_days` 且 `observed_error_runs == 0` |
   | 拍6 判绿 | ✅（sweep 回写后 `swept_hits > 0`） | ✅ probe 路径：`swept_probes > 0` 且 `pending_probes == 0`（**不要求**动条目正文） |

   不带 `--probe` 的破坏测试会**污染知识库正文**（把一条自证写成「复发 N」），
   并且**白送退役资格**：一次人造违规 = 换来 `cycle_days`（默认 90 天）后用这份守卫退役它覆盖的
   **真实经验条目**的资格（退役链读 `ever_hit`）。退役是本系统唯一的不可逆动作 —— 这条必须由账保证，
   不能靠「大家记得那次是自己造的」。

   **拆源后拍6 也跟着变了**（最容易漏的一处）：拍6 原判据依赖 `swept_hits > 0`，而它从 `pending_hits`
   派生、`pending_hits` 只在 wild 命中时递增。只放宽拍5 而不同步改拍6，probe-only 的链会从
   「拍5 红」变成「拍6 红」，整条链照样红 —— 改动等于完全无效。所以 probe 命中也必须跑一次
   `--sweep` 把 probe 账结清（拍6 的 probe 路径读 `swept_probes` / `pending_probes`）。
3. 重跑 `node scripts/trace.mjs`：退出码必须是 **0**（六拍全链可追溯）。
   仍是 1 → **不解冻**，把断掉的那一拍报给用户（报告里每拍都带 `文件:行号`，照着补）。
4. 把 `kill_switch.injection: true`（`kill_switch.distill: true` 同理）—— **一次只放一个**：
   先只放注入，观察若干次真实会话无异常，再放蒸馏。
5. 放开关后**再**复跑一次注入路径的破坏测试：确认注入面本身也拦得住（与第 2 步不同 ——
   第 2 步验的是守卫，第 5 步验的是注入）。

## 5. 为什么冻结线不放在「守卫失效」上

守卫失效（`run-guard.mjs` 的 fail-open）是**已在设计内**的行为：守卫自己坏了不许卡住提交，
只记审计。可止损的**不是**一次守卫异常，而是「整个循环不再产生新事实」——
那时继续注入等于把一份陈旧、无人证伪的语料持续喂进上下文。
所以判定锚在**六拍有没有走完**（系统是否还在活着地产生可追溯的事实），而不是某一次判红。
